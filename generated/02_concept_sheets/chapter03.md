# Chapter 3: The Interaction — Concept Sheet

---

## Interaction Models

| Term | Definition |
|------|------------|
| **Norman's Seven Stages of Action** | A model of user activity: (1) Formulate goal, (2) Plan, (3) Specify, (4) Perform, (5) Perceive, (6) Interpret, (7) Compare. |
| **Gulf of Execution** | The gap between the user's intention and the physical actions available on the system. |
| **Gulf of Evaluation** | The gap between the system's actual state and the user's ability to perceive and interpret that state. |
| **Abowd & Beale Framework** | A framework extending Norman's model, defining four components: User, System, Input, Output, and four gulf-like gaps: evaluation, execution, communication, and observation. |
| **User's model** | The user's internal understanding of how the system works. |
| **Design model** | The designer's representation of the system, embedded in the system's appearance and behaviour. |
| **System image** | The physical appearance and behaviour of the system from which the user must construct their model. |

## Ergonomics & Human Factors

| Term | Definition |
|------|------------|
| **Ergonomics** | The scientific discipline concerned with understanding interactions between humans and other system elements, optimizing human well-being and system performance. |
| **Human factors** | A discipline studying how humans interact with systems and tools, applying data and methods to design safe, efficient, and comfortable systems. |
| **Anthropometry** | The measurement of human body dimensions used to design workspaces and equipment. |
| **Cognitive ergonomics** | The study of mental processes (perception, memory, reasoning) as they affect interaction with systems. |
| **Physical ergonomics** | The study of body posture, repetitive strain, and workplace layout to prevent injury and discomfort. |

## Interaction Styles

| Term | Definition |
|------|------------|
| **Command-line interface (CLI)** | An interaction style where the user types commands as text strings; efficient for expert users but difficult to learn. |
| **Menu-based interaction** | An interaction style where users select commands from displayed lists; reduces memorization. |
| **Form-based interaction** | An interaction style where users fill in structured data fields on screen. |
| **Direct manipulation** | An interaction style where objects are represented visually and manipulated continuously (e.g., drag-and-drop). |
| **WIMP** | Window, Icon, Menu, Pointer—the fundamental elements of graphical user interfaces. |
| **Natural language interaction** | Interaction with a system using ordinary human language (written or spoken). |
| **Conversational UI** | An interface mimicking human conversation, such as chatbots or voice assistants. |
| **Touch interaction** | Interaction via direct finger contact with a screen, including tap, swipe, pinch, and long-press gestures. |
| **Gesture-based interaction** | Interaction using body movements (hand, arm, full body) interpreted by sensors or cameras. |

---

## WIMP & GUI Concepts

| Term | Definition |
|------|------------|
| **Window** | A rectangular area on the display showing the output of an application or document. |
| **Icon** | A small graphical image representing an object, action, or concept. |
| **Menu** | A list of available commands or options displayed for the user to select. |
| **Pointer** | A visual indicator (cursor) on the screen showing the current pointing position. |
| **Desktop metaphor** | A GUI metaphor modeling the interface as a desk with documents, folders, and tools. |
| **Workspace** | The virtual area within a window or application where content is displayed and manipulated. |
| **Modal interaction** | A mode in which the system's interpretation of input changes (e.g., Insert vs. Overwrite mode in text editors). |
| **Modeless interaction** | An interaction style where the same input always produces the same result regardless of context. |

---

## Feedback & Visibility

| Term | Definition |
|------|------------|
| **Feedback** | Information returned to the user indicating the result of an action or the current system state. |
| **Visibility of system status** | Norman's principle that the system should always keep users informed about what is going on. |
| **Signifiers** | Signals that communicate where an action should take place and how it should be performed. |
| **Affordance** | A property of an object that suggests how it can be used (e.g., a button affordance suggests pressing). |
| **Perceived affordance** | What the user believes an object can do based on its appearance, which may differ from its actual affordance. |
| **Mapping** | The relationship between controls and their effects (e.g., moving a mouse right moves the cursor right). |
| **Natural mapping** | Mappings that follow spatial or cultural conventions, making controls intuitive to use. |
| **Constraints** | Properties that restrict the possible actions, guiding the user toward correct usage. |
