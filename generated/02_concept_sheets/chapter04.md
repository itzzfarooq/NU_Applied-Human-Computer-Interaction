# Chapter 4: Paradigms — Concept Sheet

---

## Historical Paradigms

| Term | Definition |
|------|------------|
| **Batch processing** | An interaction paradigm where users submit jobs and receive results later, with no real-time interaction. |
| **Time-sharing** | A paradigm allowing multiple users to interact with a central computer simultaneously via terminals. |
| **Networking (ARPANET)** | The interconnection of computers across distances, enabling communication and resource sharing. |
| **Graphical User Interface (GUI)** | An interface using windows, icons, menus, and a pointer for direct manipulation of on-screen objects. |
| **Personal computing** | The paradigm of individual use of affordable, powerful computers for personal productivity and entertainment. |
| **World Wide Web (WWW)** | A system of interlinked hypertext documents accessed via the Internet; democratized information access. |
| **Ubiquitous computing (UbiComp)** | A paradigm where computing is integrated into everyday objects and environments, making it invisible and pervasive. |
| **Mobile computing** | Computing performed while the user is in motion, using portable devices with wireless connectivity. |
| **Cloud computing** | The delivery of computing services (storage, processing, software) over the internet from remote servers. |
| **Internet of Things (IoT)** | A network of physical objects embedded with sensors, software, and connectivity, enabling data exchange. |
| **Augmented reality (AR)** | A technology overlaying digital information (images, text, sounds) onto the user's view of the real world. |
| **Virtual reality (VR)** | A fully immersive, computer-generated environment that replaces the user's real-world view. |
| **Mixed reality (MR)** | A blend of real and virtual worlds where physical and digital objects co-exist and interact in real time. |
| **Conversational agent** | A software agent engaging in dialogue with users via natural language (e.g., chatbots, voice assistants). |

## Paradigm Characteristics

| Term | Definition |
|------|------------|
| **Interactivity** | The degree to which a system responds to user input in real time. |
| **Directness** | The degree to which the user's actions map directly to system responses without intermediary steps. |
| **Feedback loop** | The cycle of user action → system response → user perception that drives ongoing interaction. |
| **Visibility** | Making system functions and states apparent to the user through the interface. |
| **Constraint** | Limiting possible actions to guide correct usage and prevent errors. |
| **Visibility vs. discoverability** | Visibility means things are always apparent; discoverability means users can find features when needed. |
| **Affordance vs. constraint** | Affordances enable actions; constraints restrict them. Both guide correct interaction. |
| **Consistency** | Using the same interaction patterns and conventions throughout a system to reduce learning burden. |
