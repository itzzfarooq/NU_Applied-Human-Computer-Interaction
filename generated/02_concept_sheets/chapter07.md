# Chapter 7: Design Rules — Concept Sheet

---

## Design Principles

| Term | Definition |
|------|------------|
| **Design principles** | General guidelines and rules of thumb for creating effective, usable interfaces. |
| **Visibility** | Making system status, functions, and available actions apparent to the user. |
| **Feedback** | Providing immediate, clear information about the outcome of user actions. |
| **Consistency** | Using the same design patterns, terminology, and behaviour throughout the system. |
| **Constraints** | Limiting user actions to prevent errors and guide correct usage. |
| **Affordance** | Designing objects so their use is apparent from their appearance. |
| **Mapping** | Ensuring controls relate logically to their effects through spatial or conceptual alignment. |
| **Structure** | Organizing the interface to communicate relationships and hierarchy clearly. |
| **Simplicity** | Keeping the interface clean and minimal, showing only what is necessary. |
| **Tolerance** | Designing systems that are forgiving of user errors and allow easy recovery. |
| **Reuse** | Using consistent components and patterns to reduce cognitive load and development effort. |

## Heuristics

| Term | Definition |
|------|------------|
| **Heuristic evaluation** | A usability inspection method where evaluators rate interface elements against a set of recognized principles. |
| **Nielsen's 10 Heuristics** | (1) Visibility of system status, (2) Match between system and real world, (3) User control and freedom, (4) Consistency and standards, (5) Error prevention, (6) Recognition over recall, (7) Flexibility and efficiency of use, (8) Aesthetic and minimalist design, (9) Help users recognize/recover from errors, (10) Help and documentation. |
| **Visibility of system status** | The system should always keep users informed about what is going on through appropriate feedback. |
| **Match between system and real world** | The system should speak the user's language, using familiar words, phrases, and concepts. |
| **User control and freedom** | Users need "emergency exits" to leave unwanted states without extended dialogue. |
| **Consistency and standards** | Users should not have to wonder whether different words, situations, or actions mean the same thing. |
| **Error prevention** | A careful design that prevents problems from occurring is better than a good error message. |
| **Recognition over recall** | Make objects, actions, and options visible; minimize the user's memory load. |
| **Flexibility and efficiency of use** | Accelerators (hidden from novice users) may speed up interactions for expert users. |
| **Aesthetic and minimalist design** | Interfaces should not contain information that is irrelevant or rarely needed. |
| **Help users recognize, diagnose, and recover from errors** | Error messages should be expressed in plain language and suggest a solution. |
| **Help and documentation** | Provide searchable, task-focused help when needed, but it should not be necessary to use the system. |

## Standards & Guidelines

| Term | Definition |
|------|------------|
| **Standards** | Formal specifications and conventions for design, often industry-specific (e.g., ISO, WCAG). |
| **Guidelines** | General recommendations for design, less prescriptive than standards. |
| **ISO 9241** | International standard for ergonomic requirements of office work with visual display terminals. |
| **WCAG (Web Content Accessibility Guidelines)** | Guidelines for making web content accessible to people with disabilities; defines A, AA, AAA levels. |
| **Section 508** | US federal law requiring electronic and information technology to be accessible to people with disabilities. |
| **ADA (Americans with Disabilities Act)** | US civil rights law prohibiting discrimination, including in digital accessibility. |
| **Accessibility** | Designing products so they can be used by people with a wide range of abilities and disabilities. |
| **Universal design** | The design of products and environments to be usable by all people, to the greatest extent possible, without the need for adaptation. |
| **Inclusive design** | Design that considers the full range of human diversity, including ability, language, culture, and age. |

## Design Patterns

| Term | Definition |
|------|------------|
| **Design pattern** | A reusable, documented solution to a commonly occurring design problem within a given context. |
| **Anti-pattern** | A commonly occurring solution that is ineffective or counterproductive; a "bad" pattern to avoid. |
| **Interaction pattern** | A recurring interface component or behaviour that solves a specific usability problem (e.g., autocomplete, infinite scroll). |
| **Christopher Alexander's patterns** | The original architectural pattern concept: a pattern describes a problem, a context, and a proven solution. |
| **Gang of Four (GoF)** | Authors of the seminal design patterns book for software engineering (Gamma, Helm, Johnson, Vlissides). |
