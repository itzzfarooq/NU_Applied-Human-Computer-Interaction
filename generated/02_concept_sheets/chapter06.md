# Chapter 6: HCI in the Software Process — Concept Sheet

---

## Software Development Models

| Term | Definition |
|------|------------|
| **Waterfall model** | A linear, sequential software development process: requirements → design → implementation → testing → maintenance. |
| **V-model** | A variation of waterfall where each development phase has a corresponding testing phase. |
| **Incremental development** | Building a system in small, functional increments, each adding capabilities. |
| **Spiral model** | A risk-driven, iterative process combining elements of design and prototyping phases. |
| **Agile development** | An iterative, incremental approach emphasizing flexibility, collaboration, and rapid delivery of working software. |
| **Scrum** | An agile framework using time-boxed sprints, daily standups, and defined roles (Product Owner, Scrum Master, Team). |
| **Lean development** | A methodology focused on eliminating waste, delivering fast, and continuous improvement. |
| **DevOps** | A set of practices bridging development and operations for continuous delivery and rapid feedback. |

---

## Usability Engineering

| Term | Definition |
|------|------------|
| **Usability engineering** | A structured approach to developing usable systems by specifying, designing, and measuring usability throughout development. |
| **Usability goals** | Specific, measurable objectives defining acceptable levels of effectiveness, efficiency, and satisfaction. |
| **Usability metrics** | Quantitative measures of usability, such as task completion rate, error rate, time-on-task, and satisfaction scores. |
| **System Usability Scale (SUS)** | A 10-item questionnaire providing a global assessment of system usability; scores 0–100. |
| **NASA Task Load Index (NASA-TLX)** | A multidimensional assessment of subjective workload (mental, physical, temporal, performance, effort, frustration). |
| **Mean Opinion Score (MOS)** | A standardized measure of audio/video quality based on user ratings. |
| **Benchmark evaluation** | A formal usability test measuring performance against predefined usability criteria. |
| **Discount usability engineering** | A lightweight usability approach using inexpensive methods (e.g., heuristics, think-aloud, low-fidelity prototypes). |

## Iterative Design & Design Rationale

| Term | Definition |
|------|------------|
| **Iterative design** | A cyclical process: design → evaluate → refine, repeated until usability goals are met. |
| **Formative evaluation** | Evaluation conducted during design and development to identify problems and guide improvements. |
| **Summative evaluation** | Evaluation conducted after development to assess overall usability and fitness for purpose. |
| **Design rationale** | Documentation of the reasoning behind design decisions, including alternatives considered and trade-offs made. |
| **QOC (Questions, Options, Criteria)** | A design rationale framework capturing the key questions, alternative options, and criteria used to evaluate them. |
| **Design patterns** | Reusable solutions to common design problems, documented with context, problem, and solution. |
| **Participatory design** | Involving end users as active participants in the design process, often through workshops and co-design activities. |
| **Value-sensitive design** | A design approach that accounts for human values (privacy, autonomy, trust) throughout the design process. |
