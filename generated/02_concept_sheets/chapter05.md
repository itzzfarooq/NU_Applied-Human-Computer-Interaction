# Chapter 5: Interaction Design Basics — Concept Sheet

---

## Design Process

| Term | Definition |
|------|------------|
| **Interaction design (IxD)** | The design of the interaction between users and products, focusing on how users accomplish their goals. |
| **User-centred design (UCD)** | A design philosophy placing the user at the center of the design process, involving users throughout. |
| **Design thinking** | A human-centered, iterative problem-solving approach: empathize, define, ideate, prototype, test. |
| **Iterative design** | A cyclical process of design, prototyping, testing, and refinement based on user feedback. |
| **Double Diamond** | A design process model: Discover → Define → Develop → Deliver; divergent then convergent thinking. |

---

## Personas & Scenarios

| Term | Definition |
|------|------------|
| **Persona** | A fictional, representative user profile based on research, used to guide design decisions. |
| **Archetype** | A more abstract, role-based representation of a user type, focusing on core behaviours rather than specific details. |
| **Scenario** | A narrative description of a user interacting with a product in a specific context to achieve a goal. |
| **Use case** | A structured description of interactions between an actor and a system to achieve a specific outcome. |
| **Storyboard** | A visual narrative (like a comic strip) depicting how a user interacts with a product in context. |
| **Empathy map** | A tool visualizing what a user says, thinks, does, and feels to deepen understanding. |
| **User journey map** | A visual representation of the complete experience a user has with a product over time. |
| **Context of use** | The circumstances in which users interact with a product, including environment, social context, and task. |

---

## Navigation & Information Architecture

| Term | Definition |
|------|------------|
| **Information architecture (IA)** | The structural design of shared information environments; organizing and labeling content for findability. |
| **Navigation** | The mechanisms allowing users to move through a system's content and functions. |
| **Sitemap** | A diagram showing the hierarchical structure of a website or application. |
| **Breadcrumb** | A secondary navigation trail showing the user's location within the site hierarchy. |
| **Menu hierarchy** | The organized structure of menu items, often nested, representing available options. |
| **Progressive disclosure** | A technique of presenting information only as needed, reducing cognitive overload. |

---

## Gestalt Principles

| Term | Definition |
|------|------------|
| **Gestalt principles** | A set of visual perception rules explaining how humans group visual elements into meaningful wholes. |
| **Proximity** | Objects near each other are perceived as belonging to the same group. |
| **Similarity** | Objects sharing visual characteristics (colour, shape, size) are perceived as related. |
| **Continuity** | The eye follows smooth paths; elements arranged along a line or curve are perceived as related. |
| **Closure** | The mind completes incomplete shapes, perceiving whole objects even when parts are missing. |
| **Figure-ground** | The tendency to separate visual elements into foreground (figure) and background (ground). |
| **Common region** | Elements within a shared boundary are perceived as a group. |
| **Symmetry** | Symmetrical elements are perceived as belonging together and as being more stable. |

## Affordances, Signifiers & Feedback

| Term | Definition |
|------|------------|
| **Affordance** | A relationship between an object's properties and a user's capabilities that suggests possible actions. |
| **Signifier** | Any perceivable indicator that communicates where an action should take place. |
| **Mapping** | The relationship between controls and their effects; natural mappings follow spatial/cultural conventions. |
| **Constraint** | A limitation on possible actions that guides correct usage. |
| **Feedback** | Information about the result of an action, confirming the system has received and processed input. |
| **Visibility** | Making relevant functions and controls apparent to the user. |
| **Conceptual model** | A high-level explanation of how a system works, communicated through its design and interface. |
| **Interface** | The shared boundary across which information or control passes between a user and a system. |

---

## Prototyping

| Term | Definition |
|------|------------|
| **Prototype** | An early, simplified model of a product used to explore ideas, test concepts, and gather feedback. |
| **Low-fidelity prototype** | A rough, inexpensive prototype (paper sketches, wireframes) focusing on structure and flow rather than visual details. |
| **High-fidelity prototype** | A polished, interactive prototype closely resembling the final product in appearance and behaviour. |
| **Paper prototype** | A low-fidelity prototype using paper and pencil to simulate interface screens and interactions. |
| **Wireframe** | A skeletal, low-fidelity layout showing the arrangement of elements on a screen without detailed design. |
| **Mockup** | A static, visual representation of a design, showing layout and visual style but limited interactivity. |
| **Interactive prototype** | A prototype that simulates user interaction, allowing users to click through screens and trigger responses. |
| **Rapid prototyping** | Quickly building prototypes to test ideas and gather early feedback before full development. |
| **Wizard of Oz** | A prototyping technique where a human secretly simulates system responses to simulate automated behaviour. |
