# Chapter 9: Evaluation Techniques — Concept Sheet

---

## Evaluation Overview

| Term | Definition |
|------|------------|
| **Evaluation** | The systematic assessment of a product's usability, effectiveness, and user satisfaction. |
| **Formative evaluation** | Evaluation during design/development to identify problems and guide improvements. |
| **Summative evaluation** | Evaluation after development to determine overall usability and fitness for purpose. |
| **Expert evaluation** | Evaluation conducted by usability experts rather than end users. |
| **User-based evaluation** | Evaluation involving actual or representative users performing real tasks. |
| **Usability inspection** | Methods where evaluators examine an interface to identify usability problems. |
| **Discount evaluation** | Quick, inexpensive evaluation methods suitable for iterative design (e.g., heuristic evaluation, cognitive walkthrough). |

---

## Inspection Methods

| Term | Definition |
|------|------------|
| **Heuristic evaluation** | Experts review an interface against a set of usability heuristics, rating severity of problems found. |
| **Cognitive walkthrough** | Evaluators step through tasks from the user's perspective, asking: (1) Will the user know what to do? (2) Will they find the control? (3) Will they interpret feedback correctly? (4) Will they see progress toward the goal? |
| **Pluralistic walkthrough** | A method where users, designers, and stakeholders walk through a scenario, discussing usability issues. |
| **Action analysis** | Breaking down user actions into fine-grained steps to identify potential difficulties. |
| **GOMS analysis** | A predictive model estimating task time and difficulty based on Goals, Operators, Methods, and Selection rules. |
| **KLM (Keystroke-Level Model)** | A GOMS variant estimating task completion time by summing time for primitive operators (K, P, H, M, R, W). |
| **Heuristic expert** | An evaluator with expertise in usability principles who conducts heuristic evaluations. |

## Testing Methods

| Term | Definition |
|------|------------|
| **Usability testing** | Observing users as they attempt to complete tasks with a product to identify usability problems. |
| **Laboratory usability testing** | Testing conducted in a controlled, dedicated facility with observation and recording equipment. |
| **Remote usability testing** | Testing conducted remotely, with users interacting with the product from their own environment. |
| **Moderated testing** | Usability testing where a facilitator guides participants and asks questions during the session. |
| **Unmoderated testing** | Usability testing where participants complete tasks independently without a facilitator. |
| **Think-aloud protocol** | A method where users verbalize their thoughts, reasoning, and feelings while performing tasks. |
| **Concurrent think-aloud (CTA)** | Users verbalize thoughts in real time while performing tasks. |
| **Retrospective think-aloud (RTA)** | Users review a recording of their session and describe their thoughts after the fact. |
| **Cued recall** | Prompts or questions used during retrospective think-aloud to help users recall their thoughts. |
| **Eye tracking** | Recording and analyzing where users look on a screen to understand visual attention patterns. |
| **Heatmap** | A visual representation of data showing areas of high and low user attention/interaction intensity. |
| **Gaze plot** | A visual trace of a user's eye movements, showing fixation points and saccades in sequence. |
| **Fixation** | A period when the eye is relatively still, processing visual information at a particular point. |
| **Saccade** | A rapid eye movement between fixation points. |
| **Scanpath** | The sequence of fixations and saccades a user follows when viewing a display. |
| **A/B testing** | Comparing two versions of a design to determine which performs better on a specific metric. |
| **Benchmark testing** | Measuring user performance against predefined usability criteria or standards. |

## Analysis Methods

| Term | Definition |
|------|------------|
| **Task analysis** | Breaking down a task into sub-tasks and steps to understand user goals and required actions. |
| **Hierarchical Task Analysis (HTA)** | A task analysis method decomposing tasks into a hierarchy of sub-tasks with defined plans. |
| **GOMS** | A family of models (Goals, Operators, Methods, Selection rules) for predicting user performance. |
| **Keystroke-Level Model (KLM)** | A GOMS variant estimating time for individual operators (keystroke, pointing, homing, mental, system). |
| **Error analysis** | Systematically categorizing and analyzing user errors to identify design flaws. |
| **Questionnaire** | A structured set of questions used to gather subjective user feedback on usability or satisfaction. |
| **System Usability Scale (SUS)** | A 10-item questionnaire providing a reliable global usability score (0–100). |
| **ISO 9241-11** | International standard defining usability in terms of effectiveness, efficiency, and satisfaction in a specified context. |
| **NASA-TLX** | A multidimensional workload assessment tool measuring mental, physical, temporal, performance, effort, and frustration. |
| **AttrakDiff** | A questionnaire measuring pragmatic quality (usability) and hedonic quality (pleasure) of interactive products. |

## Data Collection & Reporting

| Term | Definition |
|------|------------|
| **Observation** | Watching and recording user behaviour during interaction with a product. |
| **Screen capture** | Recording the user's screen during a session for later analysis. |
| **Video recording** | Capturing video of the user's face, hands, and screen to analyze behaviour and expressions. |
| **Log analysis** | Analyzing system-generated logs of user actions to identify patterns and problems. |
| **Survey** | A method of collecting structured feedback from a large number of users. |
| **Interview** | A one-on-one conversation with a user to gather in-depth qualitative feedback. |
| **Focus group** | A guided discussion with a small group of users to explore perceptions and opinions. |
| **Affinity diagram** | A technique for organizing qualitative data (e.g., usability observations) into thematic clusters. |
| **Severity rating** | A scale assessing the seriousness of a usability problem (e.g., 0=not a problem, 4=usability catastrophe). |
| **Triangulation** | Using multiple methods or data sources to validate findings and increase confidence in results. |
